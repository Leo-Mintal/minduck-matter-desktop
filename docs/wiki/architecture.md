# Architecture

## Current Electron implementation

- The desktop entry sets Chromium's `--lang=zh-CN` before either the main shell or isolated pet host starts. Fresh Matter/shared QA locale providers therefore default to Simplified Chinese, while their existing valid `matter.locale` preference still takes precedence. This desktop-only default also applies when packaging a fresh remote Web `dev` checkout; no shared frontend source or saved preference is rewritten. The switch does not translate role-generated macOS menu labels.
- The default desktop route creates one Electron `BrowserWindow`. `src/main.cjs` owns the fixed Matter `WebContentsView`, the browser chrome views, and the window layout. `src/electronBrowserHost.cjs` owns every right-side Chromium page, including tab creation, navigation guards, isolated session usage, tab lifecycle, and native view layout. The right panel is part of the same native application window and uses Matter's custom UI rather than an external browser window.
- The default app opens no DevTools port and no longer starts the Matter Browser extension worker. `src/client-runtime.cjs` connects one login-authenticated `/api/client-runtime/ws` for both built-in browser and local execution. It creates no device registration, pairing or persistent device token. Browser capability remains independent of local Shell system authorization; the old built-in browser pairing/settings controller is no longer loaded by main.
- `src/browser-device/tools.cjs` reuses the pinned 1.3.2 extension tool engine in a private main-process VM through two explicit native host hooks in `extensions/matter-browser/background.js`. It does not duplicate the 15 schemas or tool semantics. `page-runtime.cjs` injects allow-listed helpers into private CDP worlds, including same-origin and cross-process child frames. It owns each task page's debugger until cancellation, suspension or tab closure. The extension-facing compatibility API keeps its original nine page-level methods; native child-frame attachment is not exposed there.
- Native execution retains the engine's task-group/site gates, per-device serialization, ref lifecycle, trusted input and navigation waits. Upload reads only same-origin `/media/` bytes with redirect refusal and a 20MB declared/streamed limit, then uses File/DataTransfer in the page. Runtime identity and context are account/origin-bound; logout and connection loss stop subsequent operations. JS dialog handling uses the last verified unexpired identity only while an observed task-page dialog pauses renderer evaluation. Cancellation cannot roll back actions or JavaScript already submitted to a page.
- Desktop readiness comes directly from main-process snapshots, published to the trusted Matter DOM with account and a timestamp every second. The frontend expires snapshots after 3.5 seconds, listens for native updates, never discovers itself through HTTP and never receives proof/token in DOM. Browser readiness, Shell executor readiness, native access requests and server reconnect states are separate. Ordinary Web still discovers this computer through the bridge; JWT verification uses independent Node fetch (2.5s) while Web waits 3.5s. Verification failures return specific status/reason; occupied bridge ports retry until available.
- Main injects a short-lived `X-Matter-Runtime` proof into same-origin/account API requests. The `127.0.0.1:19473/context` bridge exposes only status/context to an exact-origin, authenticated same-account Web page; it exposes no command endpoint. When Electron omits Origin, main restores it only for the exact loopback context endpoint and a trusted Matter request referrer; the bridge still verifies the login JWT. It never selects another computer from an account-wide online list. The local browser smoke covers real Electron and runtime WS; see [built-in capabilities](../builtin-browser-device.md) for boundaries and commands. `src/extensionApiBridge.cjs` remains available to explicit compatibility tests and experimental extension entry points, but is not started by main.
- The page-tree helper reads rendered descendant text for interactive control names after explicit labels, so short nested button/link/ARIA-control labels remain attached to their actionable refs and hidden child text is omitted. The native smoke covers a fixed footer with a nested two-character label, interactive filtering and a fixture-only ref click. Helpers are read from disk on first injection into a document; an already initialized page keeps its previous helper until reopened or reloaded.
- The application entry point always uses Electron's bundled Chromium. `src/chromium-shell.cjs`, `src/chromiumBrowser.cjs`, and `minduck-matter-chromium/` remain opt-in compatibility experiments and are not reachable from the packaged app entry point.
- `minduck-matter-chromium/` remains a standalone macOS Apple Silicon prototype that downloads an official Chromium snapshot, starts it with an isolated profile, and loads the existing `extensions/matter-browser` and `extensions/xiaohongshu` folders unchanged. It never falls back to the user's Google Chrome profile.
- The Chromium prototype is packaged as an unsigned outer `Minduck Matter Chromium.app` whose bundled Chromium runtime receives the Matter URL and unpacked extension paths at launch. Its `chromium:smoke` command starts Chromium with a temporary profile and asserts that the Matter Browser Service Worker has `tabs`, `scripting`, `debugger`, and `tabGroups` APIs. It is a compatibility prototype, not a maintained Chromium source fork.
- The packaged Electron build contains no prebuilt Chromium app. Its macOS package script signs and notarizes by default: it delegates the complete nested Electron signature to electron-builder using a Developer ID Application identity, enables Hardened Runtime with main/inherited entitlements, submits the final DMG through a local `notarytool` keychain profile, and staples its ticket. `MINDUCK_MACOS_SIGN=0` is reserved for unsigned local test DMGs. It never applies post-build deep signing because that can make Electron Framework and `libffmpeg.dylib` use incompatible signing teams. It does not compile, patch, or vendor Chromium source.
- Matter is a single non-closable main view whose URL defaults to `https://matter.minduck.com`. `scripts/build-web.cjs` stages only the Web project's `dist` output under generated `web-dist/`, included in `app.asar`. `pnpm start` builds the selected local `MINDUCK_WEB_SOURCE`; `pnpm dist:mac` instead shallow-clones the latest remote `dev` branch to a temporary directory and never reads that checkout's current branch or uncommitted changes. The packager derives the remote from the sibling repository's `origin` by default, or `MINDUCK_WEB_REMOTE` can select it explicitly. `MINDUCK_WEB_DIST` is ignored for normal releases. The explicit `MINDUCK_WEB_ALLOW_PREBUILT=1` escape hatch accepts verified CI artifacts or a user-requested local build; it retains signing/notarization and requires recording local input provenance rather than claiming the latest remote Web source.
- `src/bundledFrontend.cjs` installs an exact-origin HTTP(S) protocol handler in the default Electron session. The configured Matter origin serves local bundled files with correct MIME types, no-store caching and SPA navigation fallback. `/api`, `/media`, `/p` and their subpaths preserve original network requests through `net.fetch(request, { bypassCustomProtocolHandlers: true })`, including auth, uploads and SSE streams. Other origins pass through unchanged, and the right-browser session is separate. No frontend source is duplicated or modified, and no Node.js or Bash API is exposed to the Matter renderer.

Both accept HTTP only for loopback or the exact test origins `http://192.168.11.70:3001` and `http://192.168.11.70:8080`. Keeping the document's existing origin preserves local storage, relative API paths, BrowserRouter and extension presence. The bundled UI loads without network access; business operations still require the backend. A frontend load failure shows `src/matter-unavailable.html`. Backend failures are handled by the Web application's existing request UI. Changing the backend setting restarts the app and its exact-origin protocol handler.

Only packaged arm64 macOS apps installed in Applications can update; source previews and mounted installers cannot install updates. The fixed HTTPS generic feed is `https://matter-desktop.yogeeai.com/download/`, with `latest-mac.yml`. Silent checks never download; an explicit confirmation downloads the version-matched ZIP with SHA-512 verification. Exact arm64 ZIP/DMG filenames, digest/size metadata, strict versions and no downgrade/prerelease policy are enforced. Progress is visible in the existing 28px rail button and the Dock. Native Squirrel preparation/signature verification completes before stopping the companion and calling `quitAndInstall`; active tasks can defer installation, including tasks starting during native preparation. Its first tab and user-created tabs open a local search page with the shared Minduck brand icon, with no website-facing preload bridge or Node.js APIs. ## Matter local execution (2026-11-13, native file access)

`src/local-exec/` is a main-process executor. Login and Seatbelt readiness enable `native-file-access-v1` without a global Full Disk Access prerequisite or device pairing. Startup does not open the protected TCC database or System Settings. The manual Full Disk Access menu retains a readonly probe and settings entry for tasks that need it; the app never self-grants access or changes TCC records.

Client and server negotiate `localPermissions:{version:1,mode:"macos-native"}`. `shell_permission` now advertises the ability to request filesystem access, not missing FDA. A new client on an old server fails closed with `server_upgrade_required`; a new server refuses the old client's permission flow with `client_upgrade_required`. Browser capability remains independent.

`local_request_permission` requires a concrete `path`, with optional `reason`. `system-folders.cjs` performs a minimal real access from Electron main before the sandboxed command or worker; macOS owns the resulting privacy prompt and remembered decision. Explicit paths are also preflighted, after any required Matter task approval. Desktop/Documents/Downloads, iCloud and individual File Provider roots coalesce concurrent requests. The broker remembers denials for the same run/resource, rechecks successful access next time, and validates the active account/generation before and after waiting. Disable, logout and cancellation prevent a late approval from executing a task.

Access denial preserves `os_access_denied`, `denied`, the target, error code, execution/partial-effect flags and `denial_source:"unknown"`. POSIX or ACL denial cannot prove a TCC Deny click. The UI and model stop the affected task and explain access was not obtained, rather than calling the OS unsupported. A successful preflight grants neither permanent Matter authority nor proof of write access. Selected application-data/config paths now require native Matter confirmation before this OS preflight; a system refusal revokes the overlapping task grant. Bundle purpose strings include File Provider access; real allow/deny clicks remain user acceptance work, without TCC resets.

Photos access also requires the main Hardened Runtime signature to include `com.apple.security.personal-information.photos-library` and the bundle to declare `NSPhotoLibraryUsageDescription`. On 2026-11-16 at 10:33, the local `tccd` log explicitly refused the installed 0.1.10 application's Photos prompt because that entitlement was missing; the installed Info.plist also lacked the purpose string. Both declarations are now covered by packaging regressions. Source configuration is corrected; a signed and notarized 0.1.10 test DMG/ZIP is available in `release/photos-permission-test-20261116/`, with both declarations verified in the final mounted DMG. The installed client has not been replaced, and the actual system-prompt check remains user acceptance work. Restarting the API or the old client cannot change installed signature entitlements. This does not reset TCC, grant access, or guarantee a new prompt after a remembered system decision.

Default cwd and relative file paths use the user home; explicit cwd/path uses the requested location. No tool call allocates a conversation folder or writes a workspace mapping. Parent directories are created only by actual output writes. Shell/worker caches live inside the short-lived private temp directory and are removed on completion. `cleanup-workspaces.cjs` runs once on startup and uses only `rmdir` for recorded or recognizable legacy empty folders under the old configured root; user artifacts, nonempty caches, links and unrelated directories remain untouched.

`path-access.cjs` gates `.netrc`, `.npmrc`, `.pypirc`, Keychains, Application Support, Messages, Mail and the current userData path. `access-dialog.cjs` shows a parented native confirmation with path, purpose, read versus modify scope and service-disclosure text; denial is the default. Grants are memory-only, scoped to account/conversation/run and cleared on executor stop. Seatbelt applies the same path/read-write grants to Shell and file workers, including paths outside cwd; ordinary paths retain their existing behavior. The five credential directories `.ssh`, `.aws`, `.gnupg`, `.kube`, `.docker` and the existing system configuration exclusions remain blocked. Network remains closed unless `needs_network=true`.

The client advertises `clientRuntime.fileOpen=1` when its native opener is available. The backend mounts `local_open_file` only for that authenticated, Shell-ready runtime. This path-only tool reuses active-account, cancellation, native-access and sensitive-path checks before `open-file.cjs` validates an existing regular file or directory, rechecks its canonical path and stat identity, then calls Electron `shell.openPath` with only that path. There is no extension allowlist or application override: files use system associations, project directories use the system's default directory behavior, and installed apps may be addressed by their actual local paths. URLs, application names, commands, launch arguments and special files are not accepted. Opening a project or installer does not prove execution or installation. Shell sandbox policy is unchanged. `open_requested` confirms only that the system accepted the default-open request, not a visible window or inspected content; `open_failed` preserves the launch error and prohibits automatic retries. A native access denial stops before launching, and legacy runtimes cannot dispatch the tool.

The current conversation stream stores and displays the actual Shell command, cwd, output, exit code and status. Unknown results are not automatically replayed. `pnpm test` and `test:local-exec` use injected permission state and disposable homes with real Electron/runtime WS/Seatbelt, without changing the user's TCC. The test app has a distinct app ID/profile and needs its own manual system permission. Its Developer ID signature must retain the same team and bundle ID on subsequent builds; an ad-hoc, hash-based signature cannot provide that stable identity. Moving from the previous ad-hoc test package to Developer ID signing can require one new system grant; production and test app permissions are not copied between identities.

## Local/cloud cooperation (2026-11-13)

The client declares `clientRuntime.fileTransfer=1`. Its internal `local_transfer_read` operation uses the existing authenticated controller, native access preflight, path/sensitive-root checks and sandboxed worker to read regular files in 256KiB chunks, up to 256MiB. Each chunk pins and rechecks the file stat revision; binary content does not use the UTF-8 edit/read contract.
