# Architecture

## External browser migration stopped

- On 2026-11-05 the user canceled the external-browser port and requested restoration of the original Minduck browser style. No Brave/DuckDuckGo synchronization or native build is active; Electron's bundled Chromium remains the product runtime.
- At the user's cleanup request, the unfinished source port, patches, tooling/download caches, native-only tests and build commands were removed. The port never produced an installed runtime. Historical notes remain only as development history.

## Current Electron implementation

- The desktop entry sets Chromium's `--lang=zh-CN` before either the main shell or isolated pet host starts. Fresh Matter/shared QA locale providers therefore default to Simplified Chinese, while their existing valid `matter.locale` preference still takes precedence. This desktop-only default also applies when packaging a fresh remote Web `dev` checkout; no shared frontend source or saved preference is rewritten. The switch does not translate role-generated macOS menu labels.
- The default desktop route creates one Electron `BrowserWindow`. `src/main.cjs` owns the fixed Matter `WebContentsView`, the browser chrome views, and the window layout. `src/electronBrowserHost.cjs` owns every right-side Chromium page, including tab creation, navigation guards, isolated session usage, tab lifecycle, and native view layout. The right panel is part of the same native application window and uses Matter's custom UI rather than an external browser window.
- The default app opens no DevTools port and no longer starts the Matter Browser extension worker. `src/browser-device/controller.cjs` pairs a separate `kind=browser` device and reuses the reverse WS transport with browser schemas/MCP results, without `localExec` capability. Its safeStorage-encrypted token is stored independently in `browser-device/settings.json`; settings are sender- and main-frame-checked. The application menu provides enable/status/revoke controls.
- `src/browser-device/tools.cjs` reuses the pinned 1.3.2 extension tool engine in a private main-process VM through two explicit native host hooks in `extensions/matter-browser/background.js`. It does not duplicate the 15 schemas or tool semantics. `page-runtime.cjs` injects allow-listed helpers into private CDP worlds, including same-origin and cross-process child frames. It owns each task page's debugger until cancellation, suspension or tab closure. The extension-facing compatibility API keeps its original nine page-level methods; native child-frame attachment is not exposed there.
- Native execution retains the engine's task-group/site gates, per-device serialization, ref lifecycle, trusted input and navigation waits. Upload reads only same-origin `/media/` bytes with redirect refusal and a 20MB declared/streamed limit, then uses File/DataTransfer in the page. Browser credentials and presence are account/origin-bound; logout, disable and revocation stop subsequent operations. JS dialog handling uses the last verified unexpired identity only while an observed task-page dialog pauses renderer evaluation. Cancellation cannot roll back actions or JavaScript already submitted to a page.
- Main publishes the online native device ID through Matter's `data-matter-device` attribute; the existing Web client sends `X-Matter-Device` so service-side device filtering can select it. The local browser-device smoke covers real Electron and reverse WS without a real model. See [builtin browser device](../builtin-browser-device.md) for boundaries and commands. `src/extensionApiBridge.cjs` remains available to explicit compatibility tests and experimental extension entry points, but is not started by main.
- The page-tree helper reads rendered descendant text for interactive control names after explicit labels, so short nested button/link/ARIA-control labels remain attached to their actionable refs and hidden child text is omitted. The native smoke covers a fixed footer with a nested two-character label, interactive filtering and a fixture-only ref click. Helpers are read from disk on first injection into a document; an already initialized page keeps its previous helper until reopened or reloaded.
- The application entry point always uses Electron's bundled Chromium. `src/chromium-shell.cjs`, `src/chromiumBrowser.cjs`, and `minduck-matter-chromium/` remain opt-in compatibility experiments and are not reachable from the packaged app entry point.
- `minduck-matter-chromium/` remains a standalone macOS Apple Silicon prototype that downloads an official Chromium snapshot, starts it with an isolated profile, and loads the existing `extensions/matter-browser` and `extensions/xiaohongshu` folders unchanged. It never falls back to the user's Google Chrome profile.
- The Chromium prototype is packaged as an unsigned outer `Minduck Matter Chromium.app` whose bundled Chromium runtime receives the Matter URL and unpacked extension paths at launch. Its `chromium:smoke` command starts Chromium with a temporary profile and asserts that the Matter Browser Service Worker has `tabs`, `scripting`, `debugger`, and `tabGroups` APIs. It is a compatibility prototype, not a maintained Chromium source fork.
- The packaged Electron build contains no prebuilt Chromium app. Its macOS package script signs and notarizes by default: it delegates the complete nested Electron signature to electron-builder using a Developer ID Application identity, enables Hardened Runtime with main/inherited entitlements, submits the final DMG through a local `notarytool` keychain profile, and staples its ticket. `MINDUCK_MACOS_SIGN=0` is reserved for unsigned local test DMGs. It never applies post-build deep signing because that can make Electron Framework and `libffmpeg.dylib` use incompatible signing teams. It does not compile, patch, or vendor Chromium source.
- Matter is a single non-closable main view whose URL defaults to `https://matter.minduck.com`. `scripts/build-web.cjs` stages only the Web project's `dist` output under generated `web-dist/`, included in `app.asar`. `pnpm start` builds the selected local `MINDUCK_WEB_SOURCE`; `pnpm dist:mac` instead shallow-clones the latest remote `dev` branch to a temporary directory and never reads that checkout's current branch or uncommitted changes. The packager derives the remote from the sibling repository's `origin` by default, or `MINDUCK_WEB_REMOTE` can select it explicitly. `MINDUCK_WEB_DIST` is ignored for normal releases. The explicit `MINDUCK_WEB_ALLOW_PREBUILT=1` escape hatch accepts verified CI artifacts or a user-requested local build; it retains signing/notarization and requires recording local input provenance rather than claiming the latest remote Web source.
- `src/bundledFrontend.cjs` installs an exact-origin HTTP(S) protocol handler in the default Electron session. The configured Matter origin serves local bundled files with correct MIME types, no-store caching and SPA navigation fallback. `/api`, `/media`, `/p` and their subpaths preserve original network requests through `net.fetch(request, { bypassCustomProtocolHandlers: true })`, including auth, uploads and SSE streams. Other origins pass through unchanged, and the right-browser session is separate. No frontend source is duplicated or modified, and no Node.js or Bash API is exposed to the Matter renderer.
- The native Matter-service address dialog remains an isolated, sandboxed static page because its privileged settings IPC must not be exposed to the remote renderer. It loads the staged shared Web stylesheet and uses the public Input/Button class contract: service input is pill-shaped; text actions are pill-shaped; any future icon-only action must use the shared circular icon button contract. Its private layout CSS is limited to dialog composition and status messages, while validation, saving and restart behavior stay in the main-process IPC boundary.
- `src/matterService.cjs` still validates the backend origin. Saved settings can select another HTTPS backend; `MINDUCK_MATTER_ORIGIN` has highest priority and accepts HTTP only for loopback. Keeping the document's existing origin preserves local storage, relative API paths, BrowserRouter and extension presence. The bundled UI loads without network access; business operations still require the backend. A frontend load failure shows `src/matter-unavailable.html`. Backend failures are handled by the Web application's existing request UI. Changing the backend setting restarts the app and its exact-origin protocol handler.
- `src/updateCheck.cjs` is an independent desktop-only update boundary. The main-process application menu reads `https://matter-desktop.yogeeai.com/download/latest.json`, validates strict semantic versions and accepts only the exact adjacent `MinduckMatter-<version>-arm64.dmg` URL or its exact legacy `http://124.70.149.30:8091/` counterpart. Legacy values are normalized to the HTTPS download path before opening the system browser; it never downloads, installs, or modifies the running app. This path does not involve Matter Web or its backend. The source change ships in the next installer; the existing 0.1.5 artifact retains its old updater.
- `scripts/release-macos.cjs` is the explicit macOS release orchestrator. It accepts one target version, requires it to be no older than the local package and newer than the public manifest, first authenticates a temporary SSH ControlMaster connection to `root@124.70.149.30` (independent of the public HTTPS host), verifies the Keychain notarization profile, invokes the normal signed remote-`dev` package flow, and only then publishes an SHA-256-verified temporary DMG and atomically replaces the static manifest. The manifest retains the legacy download field so already installed clients' same-origin validation keeps working; current source resolves it to HTTPS. It has no Docker control path.
- The default all-Electron browser panel uses the separate `persist:minduck-agent-browser` session. Its first tab and user-created tabs open a local search page with the shared Minduck brand icon, with no preload bridge or Node.js APIs. Address-bar keywords and the new-tab search use the selected Bing/Google engine. Explicit HTTP(S) URLs and extension-created tabs retain their existing behavior. A Google homepage remains an optional new-tab preference.
- The restored original Minduck chrome exposes tabs, new-tab, close-panel, back/forward, reload/stop, the address field, external-open and browser settings. Assistant and local-sandbox buttons are absent; their existing host implementations and the automation extensions remain available internally.
- `src/browserPreferences.cjs` saves allow-listed search/new-tab preferences in private `browser-preferences.json`, separate from Matter and pet settings. A sandboxed modal uses the same shared frontend's `surface=settings` with a dedicated preload and sender-checked IPC. Cache clearing targets only the browser session's HTTP cache and keeps cookies. The local new-tab page uses `surface=newtab` without any preload. Cmd/Ctrl+L/T/W work from browser pages and chrome.
- Matter-origin links remain in the fixed Matter view; external HTTP(S) links requested from Matter open in the system browser. Matter-origin `/api/` and `/media/` targets download instead of replacing the Matter document, whether opened in a new window or navigated in place; subframe redirects to them stay blocked.
- The macOS application icon uses the full-bleed square artwork in `build/sidebar-logo.svg`; the source has no rounded rectangle clipping or transparent corner padding. The embedded duck artwork, its position and scale are preserved. The build renders every system icon size into legacy `build/icon.icns`, then compiles the same square source through Icon Composer with `actool` into `build/AppIcon.icns` and `build/Assets.car`. Packaging sets both `CFBundleIconFile` and `CFBundleIconName` to `AppIcon` and uses the compiled ICNS as Electron Builder's macOS icon input. Icon Composer/macOS applies the final system icon mask, Dock treatment and hover magnification; no runtime icon replacement is used.
- The default Agent Browser session keeps its browser and Xiaohongshu login state separate from Matter. The native runtime maps the pinned tool engine to page-scoped Electron operations; the old bridge still supplies missing APIs in explicit extension compatibility tests. It is intentionally scoped to this extension rather than promising full Chrome-extension compatibility.
- The desktop pet is a self-contained Coopanion integration in `src/companion/`, backed by the pinned 0.2.16 source/runtime in `vendor/coopanion/runtime/`. The main shell owns its Settings/show/hide lifecycle and two explicit shortcuts: activate Matter preserving the page, or activate Matter at `/new-chat`. The isolated pet preload and guarded native host forward only these allow-listed actions through a per-launch authenticated loopback bridge; its credentials stay in the child environment. Core runs in Node mode; the official desktop-pet host runs with this app executable in a separate Electron child and profile. No standalone Coopanion application is launched.
- The ordinary default duck API 2 pack in `src/companion/figures/minduck-duck/` is bundled and selected for new profiles; it includes the user-optimized work SVG. The unchanged Suit Duck remains an optional pack. The upstream sandbox and host clock run its motions, work/ask flows, walk, drag and drop. No Matter business-state or credential coupling is added.
- Settings opens explicitly from the application Settings menu (CmdOrCtrl+,) or the pet menu. The original console uses its own persistent Electron session and a guarded local protocol proxy, separate from the Matter protocol handler; sandboxed figure frames cannot call Core APIs. The pet Exit action closes the pet only; client quit stops Core and its host.
- Configuration and logs live under `<userData>/companion/`; no standalone Coopanion data is imported. Fresh profiles use loopback console port 17888 (with upstream port fallback) and pet port 17897, remembered position, microphone off, telemetry off, and no automatic onboarding or self-updater. Model/voice setup remains explicit in the console.
- Packaged Core/TS/native dependencies and figures are extraResources outside ASAR. `check:companion` verifies presence and integration hashes; `test:companion` tests a real Core, host, API 2 flows/interruption/drag, console isolation, config persistence and window reopen in temporary data. See [Companion integration](companion.md).
- `scripts/build-duck-blender.py` additionally builds `build/duck-pet.blend` from the same untouched SVG. Blender imports the original paths into semantic layer controllers, keeps the layers in SVG coordinates, adds shallow Z ordering and looping 2.5D keyframes, and frames an orthographic transparent camera around the imported bounds. Blender's SVG importer does not render the source Gaussian-blur filters, so the Electron pet continues to use the original SVG renderer for the exact interactive appearance.
- `scripts/build-duck-3d-blender.py` builds `build/duck-pet-3d.blend` from those same paths with curve extrusion and bevels, Principled materials, an orthographic front camera, area lights, and a 96-frame looping walk cycle. Imported curves keep their SVG world transforms before receiving local animation controllers, so the rendered duck remains a single aligned character instead of scattered layers. The root controller moves through the shot while the two feet alternate swing/lift poses; the scene is a Blender 3D asset and does not replace the interactive Electron SVG renderer.
- The left Matter document is never represented as a browser tab: it is a fixed app-owned page with its own exact-origin navigation policy. Right-side tabs are the only pages exposed to the browser compatibility controller, so extension automation cannot navigate or close the Matter document.
- `extensions/xiaohongshu` is loaded into the default Agent Browser session. The Matter Browser bundle is packaged as tool-engine/helper assets for the native runtime, with its guarded host hooks; its MV3 worker is loaded only by explicit compatibility/experimental paths. The retained extension-popup route is not exposed by the simplified chrome.
- In the Electron browser host, browser tabs are individual `WebContentsView` instances. Only the selected browser tab is visible beside the always-visible Matter view, and its theme-aware browser chrome exposes generic tabs, navigation controls, an address bar, and an external-open action.
- The top-right close button collapses the browser panel without closing its tabs. Matter expands to the available width; the remaining browser-open button restores the active tab. Explicit tab selection or creation also reopens the panel. Panel visibility is owned by `ElectronBrowserHost`, independently of tab lifetime.
- Browser chrome is built from the Web project's `src/desktop/` entry with `build:desktop-shell`, importing the actual shared Panel, Button, Input, Icon, ResizeHandle and design/styles.css. Desktop loads generated `web-dist/desktop-shell/index.html` for toolbar and resizer surfaces; there is no second handwritten toolbar/style/icon copy. The browser passes `bodyScrollable={false}` to the shared Panel: navigation is fixed and never mounts an overlay scrollbar. The tab strip retains keyboard/active-tab auto-positioning while its native horizontal track is hidden. Icon buttons are circular; the address field and text tabs are pill-shaped. The Web Panel's icon actions also use the shared pill-radius token.
- The address field uses the standard shared Web Input with `shape="pill"`: common form height, responsive typography, theme colors, borders and focus state. It has no inline icons or submit button; Enter submits, Escape restores the active URL, and the separate system-browser action remains outside. Tab containers use equal 6px horizontal padding and a 6px label/close gap; label Buttons add no horizontal padding. Tab text-buttons have transparent hover/pressed/focus backgrounds while the active tab container marks selection. The close Button wraps the shared 16px Icon in 2px padding, producing a 20px circular hover surface. All exceptions are scoped to the shared desktop entry. The experimental Ego Lite appearance and tokens have been removed at the user's request. The native toolbar height follows measured content; the smoke checks public-field geometry, zero inline icons, label state transparency, compact close dimensions, navigation, themes and live resize.
- Browser navigation state is kept on each host tab independently of the shell DOM: pending addresses are shown immediately, committed main-frame and in-page navigations replace them, and failed loads retain a retryable target with a compact loading/error indicator in the Tab and toolbar. This keeps Tab switching and Chromium page lifetime independent from the shell DOM.
- `src/agentCursorOverlay.cjs` injects a pointer-events-free shadow-DOM overlay into Agent Browser web pages only. `src/assets/agent-cursor.svg` is the user-supplied `andrsrxn--cursor.svg` arrow, rendered at 28px with a light outline shadow for dark backgrounds. Its 3.5px hotspot aligns the arrow tip with the actual event coordinate. The compatibility layer updates it for CDP mouse events and hides it during page screenshots; Matter Web, extension pages, and the user's system cursor are unaffected.
- The browser shell receives the resolved Matter theme through the main process. `src/main.cjs` samples the Matter view's `data-theme` and the shared `matter.theme` preference, then publishes changes to the browser shell; the shell styles are based on the web project's color, geometry, typography, motion, and Material Symbols tokens.
- `src/rightPanelLayout.cjs` places Matter and the browser directly next to each other with the Web Panel's 1px divider, without the previous 8px gap/insets or inner rounded clipping. The native contentView has an explicit opaque canvas backing. On macOS, only the Matter child content starts below a 36px title-bar safety region (24px for native controls plus a 12px gap before Matter content) so `hiddenInset` traffic-light controls cannot cover Matter navigation; the right native panel, toolbar and browser remain full height. The trusted local toolbar reports its measured natural height and resolved Web geometry/color tokens via validated IPC; startup fallbacks cover initial loading. Width defaults to Web's 384px and clamps to its 380px minimum, 300px reserve and 0.82 maximum ratio. `src/panelMotion.cjs` drives open/close over 220ms with an ease-out native frame: Matter width, panel container, chrome and active page move together; rapid reversal starts from the current frame. The Web shell adds matching toolbar fade/translation and a short tab-navigation transition, while CSS respects `prefers-reduced-motion`. Window resize and ResizeHandle drag cancel the motion and immediately restore direct per-frame bounds updates. Web's shared ResizeHandle coalesces pointer moves to one update per animation frame; main keeps a stable full-window transparent input surface only while dragging and saves the final width on release. The native surface owns capture because moving/expanding a WebContentsView can release DOM pointer capture; ordinary Web usage retains DOM capture. Blur/cancel/closing clears capture. Unchanged native bounds and colors are not reapplied.
- On macOS, startup checks Full Disk Access by opening (without reading) the protected TCC database read-only. Missing access shows one native dialog per process launch, linking to System Settings; saved acknowledgements and app versions do not suppress this check. Existing OS grants skip the prompt. The app cannot self-grant access or guarantee that uninstall clears macOS TCC records; its app menu retains the native System Settings shortcut.

- The independent Local Agent conversation UI, chat preload/IPC, model credentials client, Go Gateway, local file/Bash tools and their build resources have been removed. Browser control now uses the native browser-device runtime for Matter; the separate Local Agent conversation remains removed. `src/desktopSettings.cjs` retains the legacy `agent-settings.json` filename for service, width and permission preferences, and ignores retired chat switches. A saved service address that current origin rules reject loads as unset (default service) while the other saved fields are kept; an unreadable or non-object file still falls back to all defaults. Saved chat data and credentials are not proactively deleted or read.

## Matter local execution (2026-11-07, system authorization)

`src/local-exec/` is a native device client, never a renderer execution bridge. The independent settings page, preload, IPC and menu item are removed. Startup requests system permission before login; actual Full Disk Access plus a current Matter account automatically enables `system-access-v1` and pairs `kind=desktop`. The controller preserves exact-origin/account binding, encrypted credentials, request headers, cancellation and conflict checks. Failed pairing backs off; server revocation stays disabled for that account for this process session.

After OS authorization, explicit cwd/path may target any system-user-accessible directory without a picker; per-conversation default workspaces remain under `~/Matter`. Shell and the unpacked short-lived file worker both use Seatbelt, private temporary/cache directories and a whitelist environment. Sensitive credentials, Keychains, Application Support and userData stay excluded from both reads and writes, including Shell. Network is closed unless a call declares `needs_network=true`. Revocation is checked before calls and on the one-second lifecycle poll, which cancels active transport calls; regrant reconnects. Account changes cancel the previous connection and bind the new account. Full Disk Access does not bypass OS file permissions or the credential exclusions.

Same-identity signed upgrades retain OS permission where macOS preserves it; there is no version-based re-request or TCC reset. Removing an app does not guarantee removal of its OS grant. `pnpm test` and `pnpm run test:local-exec` validate the policy with injected permission state, disposable homes, real Electron/reverse WS/Seatbelt, and no changes to the user's TCC settings. First actual authorization in a freshly installed signed build remains a manual system action.
